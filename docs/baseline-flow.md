# ORRAK Baseline Flow

이 문서는 현재 오르락 앱을 이후 개선 작업의 기준 흐름으로 고정하기 위한 간단한 정리입니다.

## 기준 원칙

- 앱의 핵심 목적은 `60초 집중력 측정 -> 바로 해석 -> 바로 다음 행동 제안`입니다.
- 한 화면에 너무 많은 정보를 몰아넣지 않습니다.
- 홈, 코치, 기록, 결과는 각각 역할이 분명해야 합니다.
- 세그먼트 메뉴는 `정보 분산용`으로만 사용하고, 첫 화면 이해를 방해하지 않도록 유지합니다.

## 기본 화면 흐름

1. `SplashScreen`
   - 앱 진입
2. `OnboardingScreen`
   - 앱 가치와 핵심 사용 이유 안내
3. `HomeScreen`
   - 오늘 상태 확인
   - 바로 측정 시작
   - 추천/패턴 요약 확인
4. `MeasureScreen`
   - 60초 3단계 측정
   - 반응 속도
   - 선택적 주의
   - 지속 집중
5. `ResultScreen`
   - 측정 결과 요약
   - 오늘 상태 해석
   - 바로 실행할 행동 제안
6. `AiCoachScreen`
   - 할 일 쪼개기
   - 미루기 극복
   - 컨디션 코칭
   - 5분 팁
   - 방해 차단
7. `RecordScreen`
   - 요약
   - 성장
   - 배지

## 화면별 역할

### Home

- 오늘 측정 전 상태를 가장 짧게 보여주는 화면
- 핵심 CTA는 `지금 측정`
- 세그먼트는 `오늘 / 추천 / 패턴`

### Measure

- 측정 외 요소를 최소화
- 입력 실수 없이 3단계를 끝내는 데 집중

### Result

- 세그먼트는 `요약 / 상태 / 실행`
- 긴 카드 누적보다 탭별 핵심 정보 우선
- 결과를 보고 끝나는 것이 아니라 `다음 행동`으로 이어지게 구성

### Coach

- 중복 설명 제거
- 선택한 코치와 입력/결과 중심
- 사용자가 “지금 뭘 적고 무엇을 받는지” 즉시 이해 가능해야 함

### Record

- 세그먼트는 `요약 / 성장 / 배지`
- `성장` 내부는 `성장 변화 / 흐름 패턴`으로 분리
- 요약 탭은 이번 주 핵심 수치와 지난주 대비 변화만 우선 노출

## 유지할 네비게이션 원칙

- 하단 네비게이션은 `홈 / 지금 측정 / 집중 코치 / 기록`
- 측정 화면에서는 하단 네비게이션을 숨김
- 나머지 화면에서는 동일한 위치와 구조 유지

## 빌드 기준

- 출시 빌드: `npm run build`
- PC 확인용 미리보기 번들: `npm run build:preview`

## 메모

- 이후 개선은 이 기준 흐름을 깨지 않는 선에서 진행합니다.
- 새 기능을 넣더라도 먼저 `어느 화면 역할에 속하는가`를 확인한 뒤 배치합니다.
